## Item 6 · What a cancel's refund did

### Question 1: what does the detail show when the refund could not be opened?

As you guessed: **`paymentStatus: "refund_pending"` with no new request in `refunds[]`.** It also
shows `earnings.pause.reason: "booking_cancelled_unrefunded"`, and jovi-mall raises a HIGH
`PAYMENT_ISSUE` ticket against the booking, which now links back to it.

**Whether to send the operator to *Raise a refund* depends on why:**

- **Cash: no.** A cash booking has no payment to refund from, so the queue answers `404
  REFUND_PAYMENT_NOT_FOUND`. The vendor hands the money back, and the ticket is where that is
  followed up.
- **Online: yes.** It either opens the request or refuses with the reason.

### Question 2: yes, and here is the field

**`result.refund`** on `POST /bookings/:id/cancel`, and on each seat in
`result.cancelled[]` of `POST /bookings/:id/session/cancel`:

| Value | Means | What the operator does |
|---|---|---|
| `none` | Nothing was owed | Nothing |
| `requested` | A refund request is open, new or already there | Nothing; it is in the refund queue |
| `refunded` | The money is already back | Nothing |
| `manual` | No request could be opened, always the case for cash | Follow the ticket |
| `failed` | The refund step threw before recording anything | **Act: no ticket or flag exists** |

You asked for three outcomes; there are five, because "nothing owed" and "the step failed" are real
answers too. `failed` should be very rare, but it is the one case nobody else would notice, so
please give it a visible treatment.

**The response `message` follows it**, so your toast can show it as is. For example:
*"Booking cancelled — the refund must be made by hand; a ticket was raised"*. A session cancel's
message adds *"N refund(s) must be handled by hand"* when any seat needs it.

⚠ **`refund` is absent until jovi-mall is deployed with it**, so treat absent as "not known" and
fall back to the re-read `booking`. Full table: [`bookings.md` § What a cancel's refund
did](../../api/bookings.md#what-a-cancels-refund-did).

The value is also in the audit row, so the booking's activity feed records it.
